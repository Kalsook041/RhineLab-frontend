# 登录动画帧率优化

2026-10-20，本轮在保留原片节奏、粒子数量和模糊转场的前提下继续提帧，没有增加依赖或降低画布分辨率。

## 实现

- 球体3331个点；双螺旋每帧保留2700个左点、1800个右软纹理及1800个圆芯。位置、半径、透明度和前后排序继续由原代码计算。
- WebGL实例化批量提交这些原语，再一次复制回原Canvas，保留原软纹理和vignette顺序。小圆覆盖校准Canvas抗锯齿；数学几何不改。
- 软件WebGL、扩展缺失或上下文丢失时回退到原Canvas路径。GPU资源在销毁或构造失败时释放。
- 窗口尺寸只在ResizeObserver更新时读取，避免动画循环触发布局；不再反复更新未显示的WELCOME切片或写入相同属性。
- 调试seek继续等待绘制；自然进入电源/WELCOME停驻直接衔接背景ticker，避免两帧等待。

接口依据：[MDN实例化绘制](https://developer.mozilla.org/en-US/docs/Web/API/ANGLE_instanced_arrays)、[MDN混合函数](https://developer.mozilla.org/en-US/docs/Web/API/WebGLRenderingContext/blendFuncSeparate)。

## 实测

Chromium/D3D11硬件加速，1920×1080、约60Hz浏览器测试环境；测量不与自动化测试或录像并发。稳态窗口约2.8秒，入场短窗口约0.9秒。

| 场景 | 本轮优化前 | 优化后 |
| --- | ---: | ---: |
| 初始球体 | 60fps | 60fps |
| 双螺旋等待，两次采样 | 52.19 / 43.67fps | 60 / 60fps |
| 电源短区间 | 绘制45.56 / 浏览器46.67fps | 绘制58.89 / 浏览器60fps |
| WELCOME复杂入场短区间 | 约50.69fps | 约52.76fps |

这部分是此前约60Hz的无界面Chromium测量；本轮补充的高刷新率可见Chrome结果见下方。没有增加60/120fps硬性限帧，实际频率仍受刷新率、GPU、浏览器和场景负载影响。

最终另做完整的真实点击启动→电源等待→登录→WELCOME连续播放：1209个rAF样本，0脚本错误、0媒体元素。请求、授权和展开阶段约60fps；WELCOME整个阶段59.65fps，单独取字母实际入场f491–525仍为59.11fps（P95间隔16.8ms）。这与上表的跳转定位后短窗口是两种测法，保留两者以免掩盖不同进入方式下的抖动。

五个对应源时点0/24/90/144/260的粒子墨迹总量与原Canvas相差不到1%；像素边缘仍有不同抗锯齿算法的残差。没有以低全屏误差宣称逐像素1:1。曾尝试缩小WELCOME模糊区域，但没有明显收益且有微小像素差，最终已撤销，保留原效果。

1280×720、DPR2的Canvas/GPU额外对照中，五个时点墨迹量差异约1.3%–2.7%，全屏RGB平均误差0.024–0.052/255；几何和字体保持原尺寸。边缘算法仍有微小差别，未以全屏平均值代替局部视觉检查。

## 120Hz 支持与高刷新率复验

2026-10-20：系统报告1920×1080、240Hz；此前无界面Chromium只提供约60Hz回调，不能据此判断前端上限。使用本机已安装的可见Chrome、D3D11、1920×1080、DPR1，真实点击球体→等待登录→权限读取→WELCOME，保留浏览器正常同步，未使用解除限帧标志。两次独立连续播放均超过120次/秒更新；最终一次如下。

| 区间 | 浏览器rAF频率 | 动画背景提交更新频率 | rAF间隔P95 |
| --- | ---: | ---: | ---: |
| 初始球体，含启动窗口 | 182.65Hz | 180.54次/秒 | 4.3ms |
| 双螺旋登录等待 | 233.42Hz | 219.73次/秒 | 4.3ms |
| 电源入场 | 225.82Hz | 221.65次/秒 | 4.3ms |
| 身份确认 | 215.07Hz | 205.41次/秒 | 4.3ms |
| 请求接收 | 234.03Hz | 212.96次/秒 | 4.3ms |
| 权限读取 | 226.49Hz | 196.49次/秒 | 4.3ms |
| 授权白卡 | 233.41Hz | 227.55次/秒 | 4.3ms |
| WELCOME字母实际入场f491–525 | 133.82Hz | 131.14次/秒 | 20.9ms |

较早一次WELCOME入场为122.68次/秒更新，保留测量波动。最终区间脚本P95约0.8–2.2ms；120fps总预算为8.33ms，脚本计时不包含浏览器后续绘制、合成、显卡队列。rAF与motionTime变化只证明浏览器回调及应用提交次数，不等同于逐帧物理呈现；WELCOME仍有超过8.33ms的长帧，**没有宣称全程锁定120fps或零掉帧**。

本轮复用地形数字四边形的六个顶点，预计算WELCOME插值通道并缓存节点，减少逐帧数组/元组分配及选择器查找。粒子、字体、模糊、分辨率、混合顺序和音画速度不变。16个源时点的改前/改后GPU截图：前六时点逐像素相同，后十时点全屏平均绝对差不超过0.000051/255、局部通道最大差8；仍可见极少量光栅化残差，没有据此声称逐像素一致。

新增受控120Hz时钟回归：两秒240次调度持续更新球体；一秒播放仍前进一秒、源4.8秒停点不变；WELCOME包含源帧之间的姿态。这个测试禁用真实AudioContext以单独测试视觉时钟，不能当作120fps跑分或音频设备测试；正常音频另由原有集成测试覆盖。

可复测的工具（先启动项目，再在另一终端运行）：

```bash
npm run dev -- --port 4173
node scripts/measure-refresh.mjs --headed --channel=chrome
```

在高刷新率屏幕上运行，确认系统刷新率和Chrome图形加速已启用。工具默认1920×1080、DPR1，报告写到被Git忽略的`.local/performance-report.json`，不修改应用的时钟或质量。其他服务地址可传`--url=http://127.0.0.1:5173/`，较小窗口可传`--width=1600`。`--channel=chrome`使用已安装Chrome；省略时使用Playwright Chromium。可见版Playwright Chromium在本机启动返回spawn UNKNOWN，最终改用已安装Chrome；无界面结果不能代替可见窗口实测。

`--uncapped`仅用于压力诊断，会加`--disable-frame-rate-limit`和`--disable-gpu-vsync`，会出现不均匀回调，不作为显示帧率或本表数据来源。正式页面没有这些标志，也没有定时器伪造帧数。
